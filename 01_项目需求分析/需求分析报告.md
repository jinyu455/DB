# 网上购物系统需求分析报告

## 一、项目背景与范围

本系统面向小型网上商店，管理用户、商品分类、商品、库存、购物车和订单。顾客可以浏览商品、直接下单或通过购物车结算，管理员负责维护商品和库存、处理发货及查看销售统计。

## 二、用户角色与核心操作

| 角色 | 核心操作 |
| --- | --- |
| 顾客 | 浏览和按分类查询在售商品，直接下单，或将商品加入购物车后查看、修改数量、移除和勾选结算。查询自己的订单，在发货前取消订单，收货后确认完成。 |
| 管理员 | 维护用户、商品和商品分类，调整库存，查询订单并处理发货，按时间和商品查看销量与销售额。 |

## 三、功能模块

| 模块 | 模块任务 |
| --- | --- |
| 用户管理 | 新增、查询、修改和删除用户，区分顾客与管理员，按角色限制可执行的操作。 |
| 商品与库存管理 | 维护商品及分类，管理商品上下架，支持按分类查询在售商品，记录和调整可售库存。 |
| 购物车管理 | 将在售商品加入购物车，查看明细、修改数量、移除商品，选择部分或全部商品结算。 |
| 订单管理 | 处理直接下单和购物车结算，创建订单和明细，扣减库存，查询订单详情，处理取消、发货和确认收货。 |
| 销售统计 | 按订单完成时间筛选已完成订单，按商品汇总销量和销售额。 |

## 四、核心业务流程

1. **商品与库存维护。** 管理员维护分类、商品售价和库存。顾客从在售商品中选择商品和购买数量。
2. **管理购物车。** 顾客将商品加入自己的购物车，重复加入同一商品时累计数量。顾客可以修改数量、移除商品，并选择部分或全部条目结算。
3. **下单与结算。** 直接下单和购物车结算均须校验商品状态与可售库存，并按当前售价计算金额。系统在同一事务内创建订单、写入明细并扣减库存。购物车结算还须在该事务内移除本次结算的条目，保留其他条目。任一步失败时整体回滚，原购物车内容保留。
4. **订单履约。** 新订单为「待发货」，管理员发货后变为「已发货」，顾客确认收货后变为「已完成」。顾客也可取消自己的待发货订单，系统在同一事务内更新订单状态并恢复库存。
5. **查询与统计。** 订单详情关联订单、订单明细和商品，显示商品名称、成交价及数量。销售统计根据已完成订单的明细计算，不受商品现价变动影响。

## 五、核心数据与联系

| 核心数据 | 主要信息与联系 |
| --- | --- |
| 用户 | 用户编号、账号、角色。一个顾客可以有多笔订单，最多有一个购物车。 |
| 商品分类 | 分类编号、分类名称。一个分类可以包含多种商品。 |
| 商品 | 商品编号、分类、名称、当前售价、上下架状态。每个商品归属一个分类。 |
| 库存 | 商品编号、可售数量。每个商品对应一条库存记录。 |
| 购物车 | 购物车编号、所属顾客。一个购物车可以包含多条商品明细。 |
| 购物车明细 | 所属购物车、商品、选购数量。购物车与商品通过购物车明细形成多对多关系。 |
| 订单 | 订单编号、下单顾客、下单时间、订单状态、订单总额、完成时间。每笔订单至少有一条明细。 |
| 订单明细 | 所属订单、商品、购买数量、成交单价。订单与商品通过订单明细形成多对多关系。 |

## 六、业务规则与数据完整性

| 约束类型 | 规则 |
| --- | --- |
| 实体与参照完整性 | 核心数据各有主键。订单和购物车关联已有顾客，商品关联已有分类，库存关联已有商品，明细关联所属订单或购物车及已有商品。被订单引用的用户和被订单明细引用的商品不得直接删除。删除无历史订单的顾客时，一并清理其购物车及明细。 |
| 唯一性 | 用户账号唯一，每个商品只有一条库存记录。每位顾客至多有一个购物车，同一商品在同一购物车或订单中各只保留一条明细。 |
| 必填与取值范围 | 账号、角色、必需的外键、选购及购买数量、可售库存、价格和订单状态不能为空。选购和购买数量为正整数，可售库存为非负整数，售价和成交单价使用非负定点小数。角色和订单状态限于报告列出的取值，已完成订单须有完成时间。 |
| 权限与状态流转 | 顾客只能查看和操作自己的购物车和订单。只有待发货订单可发货或取消，只有已发货订单可确认收货。取消成功后只恢复一次库存。 |
| 跨表一致性 | 购物车中的商品只记录购买意向，库存到下单时才扣减。结算时重新检查商品状态、价格和库存。订单总额等于各明细的成交单价乘购买数量之和，并发下单时不得超卖。 |

主键、外键、唯一性和适用的取值范围由数据库约束落实。权限校验、订单状态流转和跨表一致性由业务逻辑与数据库事务共同落实。

## 七、需求分类

| 类别 | 内容 |
| --- | --- |
| 明确需求 | 管理用户、商品及分类、库存、购物车和订单，支持直接下单、从购物车选择商品结算及销售统计。订单与商品存在多对多关系，订单详情涉及至少三张表，下单需要事务处理。 |
| 隐含需求 | 购物车不预占库存，结算时重新检查商品状态、价格和库存。订单明细须保存成交单价，库存需防止并发超卖，取消订单需恢复库存并防止重复恢复，历史订单的关联数据需保留。 |
| 需要进一步确认的需求 | 是否加入在线支付和物流跟踪。首版由管理员手动更新发货状态。 |
