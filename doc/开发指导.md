# 网上购物系统开发指导

## 一、从公共框架开始

1. 阅读[需求分析报告](../01_项目需求分析/需求分析报告.md)，先确认各模块的业务规则。
2. 在 IDEA 打开 [Java 项目的 pom.xml](../05_JDBC应用编程/pom.xml)，使用 JDK 17 或更高版本。项目已配置 MySQL JDBC 驱动。
3. 按 [Java 项目 README](../05_JDBC应用编程/README.md) 在 Java 项目目录创建 `.env`，填写本机的 `DB_URL`、`DB_USER` 和 `DB_PASSWORD`。在 Java 项目目录运行 `mvn compile exec:exec`，看到 `JDBC connection OK (SELECT 1 returned 1).` 即连库成功。业务脚本就绪后，在本机执行建表和初始化脚本，再将 `DB_URL` 指向实际业务库。

业务代码统一写在 `05_JDBC应用编程/src/main/java/com/shop/` 下。DAO 放在 `dao`，负责执行 SQL 和读取结果。Service 放在 `service`，负责业务规则和事务。普通操作可以通过 `DBUtil.getConnection()` 获取连接，调用方用 try-with-resources 关闭。涉及多个 DAO 的同一事务，由 Service 开启一个连接并传给各 DAO，再统一提交或回滚。SQL 参数使用 `PreparedStatement` 绑定。开发时可以直接调用 Service 验证功能，后续页面也调用同一组 Service。

## 二、B 同学的数据库设计与 SQL 工作

1. **先出数据库设计初稿。** 完成实体属性、联系和 E-R 图，再转换为关系模式，明确主外键、字段类型、函数依赖与 3NF。优先跟 A、C 确认用户、商品、库存、购物车、订单和明细之间的关联，尤其是下单要用的库存字段、订单状态和完成时间。先共享表名、关键字段和约束，方便大家并行开发。
2. **先交付一版能从空库执行的 SQL。** 在 `04_数据库实现/` 整合 `create_tables.sql`、`insert_data.sql` 和 `query.sql`。建表按外键依赖排序，索引写明对应的查询。初始化数据每张核心表至少 10 条，提前约定联调用的用户、商品和订单编号。整合查询时核对至少 8 条及其类型，分别是 2 条单表条件查询、2 条多表关联查询、1 条分组统计、2 条嵌套查询和 1 条复杂业务查询。

## 三、C 同学的测试与材料整理

1. **组织系统测试。** 提前列出用例和预期结果。收到各模块后，由对应开发者先自测，C 再从空库按 README 跑一遍。汇总至少 10 个用例，覆盖用户增删改查、重复账号、商品上下架、库存不足、购物车部分结算、下单失败回滚、取消订单恢复库存和销售统计。报告记录编号、输入、预期结果、实际结果、是否通过和修复情况。
2. **汇总提交材料。** 收齐各模块运行截图、测试记录和运行说明。重点核对另外两位同学也能按 README 配置环境、执行 SQL 并运行项目。

## 四、业务开发与联调

- **模块分工待小组确认。** 确定分工后，各模块开发者先按表结构跑通一条 DAO 查询，再接入 Service，补齐业务逻辑和自测。需要跨模块调用时，先约定方法参数和事务所用的连接，再联调下单、取消和统计。
- **统一验证作业要求。** 整组至少实现 1 个核心实体的完整增删改查、2 条通过 JDBC 执行的多表查询和 1 个事务业务。下单事务要验证库存扣减与订单写入一致。购物车结算还要验证成功时只移除已结算条目，失败时保留原购物车内容。
- **各自保存 AI 使用记录。** 每人按实际参与的工作整理 Prompt、模型原始回答、人工修改和验证结果，标明对应的设计文档、SQL 或 Java 文件。最终汇入 `07_AI辅助过程/`，全组至少整理 2 个有完整修改和验证过程的案例。
